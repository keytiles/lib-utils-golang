## What changed vs previous doc version

- Added `VarPrinter.Transform func(any) any` — optional prepare step (e.g. secret masking copy) that runs only when formatting is invoked.
- Added `LogStringer` (`LogString() string`) — type-owned log form, honored **only** by `VarPrinter` (not by `PrintVar` / `PrintVarS`).
- Added `PrintVarWithTransform` / `PrintVarSWithTransform` — same as `PrintVar` / `PrintVarS` with optional eager transform; existing signatures wrap these with `nil` transform.
- Documented dispatch order: on `VarPrinter`, Transform → BytesAsString → LogStringer → PrintVarS; on `PrintVar*`, transform → Stringer → error → litter.
- `Printer` / `SPrinter` left unchanged (unused legacy interfaces).

## TLDR

- `PrintVar` / `PrintVarS` dump a value to the console or to a string; `prettyPrint` chooses compact one-liner vs multi-line.
- `fmt.Stringer` and `error` short-circuit (`String()` / `Error()`); in those cases `prettyPrint` is ignored. Otherwise dumping uses [sanity-io/litter](https://github.com/sanity-io/litter).
- Prefer `VarPrinter` in log lines so the dump string is built only when the logger actually formats the argument — do **not** call `PrintVarS` up front in logging call sites.
- For `[]byte` text payloads in logs, use `VarPrinter{TheVar: bytes, BytesAsString: true}` instead of `VarPrinter{TheVar: string(bytes)}`.
- For expensive prepare before dump (masking copy, reshape), use `VarPrinter{TheVar: v, Transform: …}` — do **not** call the prepare at the call site before wrapping.
- Types that need a log-specific form distinct from `String()` can implement `LogStringer`; only `VarPrinter` will call `LogString()`.

## How it works

- Helpers live in package `kt_utils`.
- Shared dispatch for `PrintVar` / `PrintVarS` / `*WithTransform` (after optional transform):
  1. If the value implements `fmt.Stringer` → use `.String()`
  2. Else if it is an `error` → use `.Error()`
  3. Else → litter dump (`Compact: !prettyPrint`, package names kept)
- `LogStringer` is **not** part of that shared path.

### PrintVar / PrintVarS / WithTransform

- `PrintVar(theVar any, prettyPrint bool)` — writes to stdout via `fmt.Println` or litter `Dump`
- `PrintVarS(theVar any, prettyPrint bool) string` — same formatting, returns a string (litter `Sdump`)
- `PrintVarWithTransform` / `PrintVarSWithTransform` — same, but apply `transform` first when non-nil (eager in these functions)
- Useful for ad-hoc debugging and tests
- **Important:** do not use `PrintVarS` / `PrintVarSWithTransform` inside log argument lists when the log may be dropped by level — that still builds the string eagerly. Use `VarPrinter` instead.

### LogStringer

- Interface: `LogString() string`
- Consumed only by `VarPrinter`
- Lets a type expose a log-oriented representation without changing what `PrintVarS` / `fmt.Stringer` do

### VarPrinter

- Struct fields: `TheVar any`, `PrettyPrint bool`, `BytesAsString bool`, `Transform func(any) any`
- Implements `fmt.Stringer` via value receiver `String()` → `PrintS(PrettyPrint)`
- Pointer methods:
  - `Print(prettyPrint bool)` — if `*VarPrinter` is nil, prints `NIL_VALUE`; else formats `TheVar`
  - `PrintS(prettyPrint bool) string` — if `*VarPrinter` is nil, returns `NIL_VALUE`; else formats `TheVar`
- Format order in `Print` / `PrintS`:
  1. Apply `Transform` if set
  2. If `BytesAsString` and value is `[]byte` → `string(b)`
  3. Else if value implements `LogStringer` → `LogString()`
  4. Else → `PrintVar` / `PrintVarS` (already transformed; transform not applied again)
- When `BytesAsString` is `true` but value is not `[]byte`, the flag is ignored and dispatch continues
- `PrettyPrint` is ignored when `BytesAsString` formats a `[]byte`, or when `LogStringer` / `Stringer` / `error` short-circuit
- Typical logging pattern: pass `VarPrinter{TheVar: myStruct}` (optionally `PrettyPrint: true`, `Transform: …`) as a `%s` argument so formatting runs only when the log record is emitted

### Interfaces and constants

- `LogStringer` — `LogString() string` (VarPrinter only)
- `Printer` — `Print(prettyPrint bool)`
- `SPrinter` — `PrintS(prettyPrint bool)` (no return in the interface declaration)
- `NIL_VALUE` — `"<nil>"`, used when the `*VarPrinter` receiver itself is nil

## API surface

- `NIL_VALUE` — `"<nil>"`
- `LogStringer` — `LogString() string`
- `PrintVar(theVar any, prettyPrint bool)`

- `Printer` / `SPrinter` — small interfaces for print / print-to-string style helpers

## Usage sketch

```go
import (
	"fmt"

	"github.com/keytiles/lib-utils-golang/v2/pkg/kt_utils"
)

type User struct {
	Name string
	Age  int
}

func (u User) String() string {
	return fmt.Sprintf("User{name: '%s', Age: %d}", u.Name, u.Age)
}

u := User{Name: "John Smith", Age: 36}

// Stringer short-circuit — prettyPrint ignored
s := kt_utils.PrintVarS(u, true) // "User{name: 'John Smith', Age: 36}"

// Lazy for logging: string built only if the logger formats %s
vp := kt_utils.VarPrinter{TheVar: u, PrettyPrint: false}
fmt.Printf("user was: %s\n", vp)

// Lazy []byte-as-string for logging (v1.3)
payload := []byte(`{"id":"notif-id"}`)
fmt.Printf("payload: %s\n", kt_utils.VarPrinter{TheVar: payload, BytesAsString: true})

// Lazy transform for logging (v1.4) — prepare runs only if the line is emitted
fmt.Printf("cfg: %s\n", kt_utils.VarPrinter{
	TheVar: u,
	Transform: func(v any) any {
		// e.g. return MaskSecrets(v)
		return v
	},
})

// Type-owned log form (v1.4) — only VarPrinter calls LogString()
type Cfg struct{ Token string }

func (c Cfg) String() string   { return "Cfg{Token:***}" } // example
func (c Cfg) LogString() string { return "Cfg{Token:masked}" }

fmt.Printf("cfg: %s\n", kt_utils.VarPrinter{TheVar: Cfg{Token: "secret"}})
// PrintVarS still uses Stringer, not LogStringer:
_ = kt_utils.PrintVarS(Cfg{Token: "secret"}, false)

// Complex structs without Stringer: litter compact vs pretty
type Payload struct {
	Id    string
	Title string
}
p := Payload{Id: "notif-id", Title: "Notif Title"}
compact := kt_utils.PrintVarS(p, false)
pretty := kt_utils.PrintVarS(p, true)

_ = s
_ = compact
_ = pretty
```

## Caveats

- **Do not eagerly `PrintVarS` in log lines** that may be filtered by level; use `VarPrinter` so work is deferred.
- **Do not eagerly transform/mask before wrapping** in log lines — use `VarPrinter.Transform` so prepare is deferred.
- **Do not use `VarPrinter{TheVar: string(bytes)}` in log lines** — `string(bytes)` converts eagerly; use `BytesAsString: true` instead.
- **`BytesAsString` is opt-in** — raw `[]byte` without the flag still dumps as litter `[]uint8{...}`; use that when byte values, not text, are what you want to see.
- **`BytesAsString` only applies when the (post-Transform) value is `[]byte`** — if set with another type, normal dispatch applies (flag is silently ignored).
- **`LogStringer` is VarPrinter-only** — `PrintVar` / `PrintVarS` ignore it so `String()` and `LogString()` can differ by design.
- **`prettyPrint` is ignored** when the value is a `LogStringer` (via VarPrinter), a `fmt.Stringer`, an `error`, or when `BytesAsString` formats a `[]byte`.
- **Litter output is not a stable contract** — exact formatting (package prefixes, spacing) can change with litter upgrades; treat dumps as human-readable, not golden wire format unless you pin and test them.
- **Private fields are included** in litter dumps (unlike default `fmt` for unexported-only visibility in some cases — litter reflects into structs).
- **Nil value vs nil printer:** a nil typed pointer inside `TheVar` typically dumps as `nil`; `NIL_VALUE` (`"<nil>"`) applies when the `*VarPrinter` receiver itself is nil.
- **Not a substitute for structured logging** — this is for readable dumps, not key/value log fields.
- **Nested `[]byte` fields inside structs** — litter still dumps those as `[]uint8{...}`; use a custom `Stringer` / `LogStringer` on the parent struct if needed.
