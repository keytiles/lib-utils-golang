## TLDR

- `PrintVar` / `PrintVarS` dump a value to the console or to a string; `prettyPrint` chooses compact one-liner vs multi-line.
- `fmt.Stringer` and `error` short-circuit first (`String()` / `Error()`); in those cases `prettyPrint` is ignored.
- Otherwise dumping uses [sanity-io/litter](https://github.com/sanity-io/litter).
- Prefer `VarPrinter` in log lines so the dump string is built only when the logger actually formats the argument — do **not** call `PrintVarS` up front in logging call sites.

## How it works

- Helpers live in package `kt_utils`.
- Shared dispatch for `PrintVar` and `PrintVarS`:
  1. If the value implements `fmt.Stringer` → use `.String()`
  2. Else if it is an `error` → use `.Error()`
  3. Else → litter dump (`Compact: !prettyPrint`, package names kept)

### PrintVar / PrintVarS

- `PrintVar(theVar any, prettyPrint bool)` — writes to stdout via `fmt.Println` or litter `Dump`
- `PrintVarS(theVar any, prettyPrint bool) string` — same formatting, returns a string (litter `Sdump`)
- Useful for ad-hoc debugging and tests
- **Important:** do not use `PrintVarS` inside log argument lists when the log may be dropped by level — that still builds the string eagerly. Use `VarPrinter` instead.

### VarPrinter

- Struct fields: `TheVar any`, `PrettyPrint bool`
- Implements `fmt.Stringer` via value receiver `String()` → `PrintS(PrettyPrint)`
- Pointer methods:
  - `Print(prettyPrint bool)` — if `*VarPrinter` is nil, prints `NIL_VALUE`; else `PrintVar`
  - `PrintS(prettyPrint bool) string` — if `*VarPrinter` is nil, returns `NIL_VALUE`; else `PrintVarS`
- Typical logging pattern: pass `VarPrinter{TheVar: myStruct}` (optionally `PrettyPrint: true`) as a `%s` argument so formatting runs only when the log record is emitted

### Interfaces and constants

- `Printer` — `Print(prettyPrint bool)`
- `SPrinter` — `PrintS(prettyPrint bool)` (no return in the interface declaration)
- `NIL_VALUE` — `"<nil>"`, used when the `*VarPrinter` receiver itself is nil

## API surface

- `NIL_VALUE` — `"<nil>"`
- `PrintVar(theVar any, prettyPrint bool)`
- `PrintVarS(theVar any, prettyPrint bool) string`
- `VarPrinter` — `{ TheVar any; PrettyPrint bool }` with `Print`, `PrintS`, `String`
- `Printer` / `SPrinter` — small interfaces for print / print-to-string style helpers

## Usage sketch

```go
import (
	"fmt"

	"github.com/keytiles/lib-utils-golang/v2/pkg/kt_utils"
)

type User struct {
	Name string
	Age  int
}

func (u User) String() string {
	return fmt.Sprintf("User{name: '%s', Age: %d}", u.Name, u.Age)
}

u := User{Name: "John Smith", Age: 36}

// Stringer short-circuit — prettyPrint ignored
s := kt_utils.PrintVarS(u, true) // "User{name: 'John Smith', Age: 36}"

// Lazy for logging: string built only if the logger formats %s
vp := kt_utils.VarPrinter{TheVar: u, PrettyPrint: false}
fmt.Printf("user was: %s\n", vp)

// Complex structs without Stringer: litter compact vs pretty
type Payload struct {
	Id    string
	Title string
}
p := Payload{Id: "notif-id", Title: "Notif Title"}
compact := kt_utils.PrintVarS(p, false)
pretty := kt_utils.PrintVarS(p, true)

_ = s
_ = compact
_ = pretty
```

## Caveats

- **Do not eagerly `PrintVarS` in log lines** that may be filtered by level; use `VarPrinter` so work is deferred.
- **`prettyPrint` is ignored** when the value is a `fmt.Stringer` or an `error`.
- **Litter output is not a stable contract** — exact formatting (package prefixes, spacing) can change with litter upgrades; treat dumps as human-readable, not golden wire format unless you pin and test them.
- **Private fields are included** in litter dumps (unlike default `fmt` for unexported-only visibility in some cases — litter reflects into structs).
- **Nil value vs nil printer:** a nil typed pointer inside `TheVar` typically dumps as `nil`; `NIL_VALUE` (`"<nil>"`) applies when the `*VarPrinter` receiver itself is nil.
- **Not a substitute for structured logging** — this is for readable dumps, not key/value log fields.
