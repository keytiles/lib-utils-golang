## TLDR

- `MapKeys` returns map keys as a real `[]K` slice, pre-sized to `len(m)`.
- `MapValuesSet` returns unique map values as a `*kt_sets.Set[V]` (duplicates collapsed).
- Prefer these when you want a slice/set immediately; stdlib `maps.Keys` / `maps.Values` yield iterators that you would typically `slices.Collect`.

## How it works

- Helpers live in package `kt_utils` and are generic.
- Neither helper mutates the input map.
- Nil and empty maps both yield empty results (`len == 0` / set size `0`).

### MapKeys

- Signature: `MapKeys[K comparable, V any](m map[K]V) []K`
- Allocates `make([]K, len(m))` up front, then fills by ranging over the map.
- More allocation-friendly than `slices.Collect(maps.Keys(m))` when you already know the key count (capacity is exact).
- Key order is undefined (map iteration order).

### MapValuesSet

- Signature: `MapValuesSet[K comparable, V comparable](m map[K]V) *kt_sets.Set[V]`
- Builds `kt_sets.NewSetWithCapacity[V](len(m))` and `Add`s each value.
- Duplicate values appear once in the set.
- `V` must be `comparable` (set membership requirement).
- Value order is undefined.

## API surface

- `MapKeys[K, V](m map[K]V) []K` — all keys as a slice
- `MapValuesSet[K, V](m map[K]V) *kt_sets.Set[V]` — unique values as a set

## Usage sketch

```go
import (
	"github.com/keytiles/lib-utils-golang/v2/pkg/kt_utils"
)

m := map[string]int{"a": 1, "b": 6, "c": 6, "d": 1, "e": 3}

keys := kt_utils.MapKeys(m)
// len(keys) == 5; contains "a","b","c","d","e" (order undefined)

values := kt_utils.MapValuesSet(m)
// values.Size() == 3; contains 1, 3, 6

emptyKeys := kt_utils.MapKeys(map[string]int{})
emptyVals := kt_utils.MapValuesSet(map[string]int{})
// len(emptyKeys) == 0; emptyVals.Size() == 0

_ = keys
_ = values
_ = emptyKeys
_ = emptyVals
```

## Caveats

- **Order is undefined** for both the key slice and set iteration / later `AsSlice`-style views.
- **`MapValuesSet` requires comparable values** — maps with non-comparable `V` (e.g. slices, maps, functions) cannot use it; collect to a slice another way if you need all values including duplicates.
- **`MapKeys` does not dedupe** — map keys are already unique; the slice length equals `len(m)`.
- **Input map is not copied.** Concurrent mutation of `m` while a helper runs is unsafe (same as ranging a map yourself).
- **Stdlib alternative:** `slices.Collect(maps.Keys(m))` / `slices.Collect(maps.Values(m))` work too; these helpers trade that for exact slice sizing (`MapKeys`) and set semantics for values (`MapValuesSet`).
