## TLDR

- `ValueFromPtr` safely dereferences a pointer: nil → zero value of `T`, otherwise `*ptr`.
- `Ptr` wraps a value as `*T` — still available for compatibility, but **deprecated** since Go 1.26 provides `new(expr)` and `&v` covers existing variables.
- Prefer stdlib / language forms for new code; keep using `ValueFromPtr` where nil-safe deref reduces boilerplate.

## How it works

- Helpers live in package `kt_utils` and are generic over `T any`.
- They do not allocate beyond what taking a pointer / returning a value already implies (`Ptr` returns `&t` for the parameter copy).

### ValueFromPtr

- Signature: `ValueFromPtr[T any](ptr *T) T`
- If `ptr == nil`, returns the zero value of `T`.
- Otherwise returns `*ptr`.
- Useful for optional/pointer fields when you want a concrete value without an explicit nil check.

### Ptr

- Signature: `Ptr[T any](t T) *T`
- Returns a pointer to a copy of `t` (the function parameter).
- **Deprecated:** from Go 1.26, `new(expr)` does the same for expressions; for an existing variable `var v T`, use `&v`.
- Kept for backward compatibility only.

## API surface

- `ValueFromPtr[T](ptr *T) T` — nil-safe dereference
- `Ptr[T](t T) *T` — value → pointer (**deprecated**)

## Usage sketch

```go
import "github.com/keytiles/lib-utils-golang/v2/pkg/kt_utils"

// Prefer for new code (Go 1.26+)
title := new("Notif Title") // *string
id := "notif-id"
idPtr := &id               // *string

// ValueFromPtr: nil-safe read
var missing *int
n := kt_utils.ValueFromPtr(missing) // 0

age := 50
agePtr := &age
got := kt_utils.ValueFromPtr(agePtr) // 50

// Deprecated Ptr — still works (e.g. inline struct field init)
type Recipients struct {
	UserIdTerms *[]string
}
r := Recipients{
	UserIdTerms: kt_utils.Ptr([]string{"user1", "user2"}),
}

_ = title
_ = idPtr
_ = n
_ = got
_ = r
```

## Caveats

- **`Ptr` is deprecated** — new code should use `new(expr)` or `&v`; do not add new call sites without a strong compatibility reason.
- **`Ptr` points at a copy** of the argument (the parameter), not at the caller’s original variable — same semantics as taking the address of a temporary.
- **`ValueFromPtr` cannot distinguish “nil” from “pointer to zero value”** after the call: both yield the zero `T`. If you need that distinction, check `ptr == nil` yourself before dereferencing.
- **Not a deep copy.** `ValueFromPtr` returns the pointed-to value as stored; nested pointers inside `T` are not followed.
