## Why are we doing this?

During real usage of `VarPrinter` in logging call sites, a recurring pattern appeared when the value to print is a `[]byte` that should be shown as human-readable text (e.g. JSON or plain-text payload):

```go
LOGGER.Debug("payload: %s", kt_utils.VarPrinter{TheVar: string(bytes)})
```

- `VarPrinter` exists so expensive string construction is **deferred** until the logger actually formats the `%s` argument (log level allows emission).
- `string(bytes)` at the call site runs **eagerly** when the struct literal is evaluated — before the logger decides whether to emit the line — so the lazy benefit is lost.
- Passing raw `[]byte` to `TheVar` is lazy, but the default litter dump renders it as `[]uint8{72, 101, ...}`, not as readable text.
- We **must not** assume every `[]byte` should print as a string — binary payloads, hex views, and litter's native slice dump are all valid depending on context.

**Goal:** provide a backward-compatible, opt-in way for call sites to log `[]byte` as string **without** eager conversion, while keeping explicit control over when string formatting is desired.

## What will be changed?

- Add `BytesAsString bool` field to `VarPrinter` in `pkg/kt_utils/var_printing.go`.
- Handle the flag lazily in `Print` / `PrintS` — when `true` and `TheVar` is `[]byte`, convert to string only at format time.
- Add unit tests covering output, nil/empty slices, flag ignored for non-`[]byte`, and regression that raw `[]byte` without the flag still uses litter.
- Create companion feature doc `docs/VarPrinting-v1.3.md` (self-contained, inheriting v1.2 content + changelog for v1.3).
- Note the new feature under `CHANGELOG.md` release **2.1.0**.

**Not changed:**

- Existing `VarPrinter` fields (`TheVar`, `PrettyPrint`) behavior
- `PrintVar` / `PrintVarS` dispatch order (flag is handled on `VarPrinter`, not in `PrintVarS`)
- Default behavior when raw `[]byte` is passed without `BytesAsString: true`

## Decisions we made

### Options considered

Several backward-compatible approaches were evaluated:

- **Option A — Wrapper type `BytesAsString []byte` with `String()`**
  - Reuses existing `fmt.Stringer` short-circuit in `PrintVarS`.
  - Call site: `VarPrinter{TheVar: kt_utils.BytesAsString(bytes)}`.
  - Pros: minimal API change, explicit opt-in, works with `PrintVarS` too.
  - Cons: callers must know about the wrapper type.

- **Option B — Constructor helper `VarPrinterBytes(b []byte) VarPrinter`** *(initially implemented, then superseded)*
  - Internally wraps bytes in unexported `bytesAsString` (same mechanism as A).
  - Call site: `kt_utils.VarPrinterBytes(bytes)`.
  - Pros: cleanest log call site; hides implementation detail; same lazy behavior as A.
  - Cons: one more exported function; separate from struct-literal pattern.

- **Option C — Bool field on `VarPrinter` (e.g. `BytesAsString: true`)** *(chosen)*
  - Conversion deferred inside `Print` / `PrintS` when flag set and `TheVar` is `[]byte`.
  - Pros: keeps struct-literal pattern; familiar `VarPrinter{TheVar: ...}` usage.
  - Cons: field only meaningful for `[]byte`; silent no-op for other types; widens struct API.

- **Option D — Separate struct type `VarPrinterBytes`**
  - Pros: type-safe separation.
  - Cons: two types to learn; cannot use single `VarPrinter` everywhere.

- **Option E — General `LazyVarFormatter` interface**
  - Pros: extensible beyond `[]byte`.
  - Cons: larger surface area; overkill for the immediate need.

- **Option F — Default `[]byte` → string in `PrintVarS`**
  - Pros: simplest call site for the common text case.
  - Cons: **breaking / surprising** for binary data and anyone relying on litter's `[]uint8{...}` dump; rejected.

### Chosen design: Option C

`BytesAsString` on `VarPrinter` is the chosen approach:

- Opt-in and explicit — no assumption that all `[]byte` values are text.
- Backward compatible — zero value `false` means existing call sites unchanged.
- Keeps the familiar struct-literal logging pattern.
- Conversion handled in `VarPrinter.Print` / `PrintS`, not in global `PrintVarS` dispatch.

### Design details (locked)

```go
type VarPrinter struct {
    TheVar        any
    PrettyPrint   bool
    BytesAsString bool
}

func (vp *VarPrinter) PrintS(prettyPrint bool) string {
    if vp == nil {
        return NIL_VALUE
    }
    if vp.BytesAsString {
        if b, ok := vp.TheVar.([]byte); ok {
            return string(b)
        }
    }
    return PrintVarS(vp.TheVar, prettyPrint)
}
```

**Lazy evaluation flow:**

1. Call site: `VarPrinter{TheVar: bytes, BytesAsString: true}` stores the slice reference; no string allocation.
2. Logger receives `VarPrinter` as `%s` argument.
3. If log level filters the line out → `String()` is never called → no conversion cost.
4. If emitted → `VarPrinter.String()` → `PrintS()` → `BytesAsString` branch → `string(b)`.

**Backward compatibility notes:**

- `PrettyPrint` is ignored when `BytesAsString` formats a `[]byte` (no litter involved).
- `BytesAsString: true` with non-`[]byte` `TheVar` falls through to normal `PrintVarS` dispatch (flag silently ignored).
- Nil `[]byte` in `TheVar` formats as `""` (consistent with `string(nil)`).

### Explicitly out of scope (v1.3)

- **`json.RawMessage`** — distinct named type; does not match `[]byte` type assertion; callers can cast: `TheVar: []byte(raw)`.
- **Nested `[]byte` fields inside structs** — litter still dumps those as `[]uint8{...}`; separate concern (custom `Stringer` on parent struct).
- **Hex / base64 formatting** — future flag or helper if demand arises.

## Testing

`TestVarPrinter_BytesAsString` following existing GIVEN / WHEN / THEN style:

- **Output** — `VarPrinter{TheVar: []byte("hello"), BytesAsString: true}.String()` equals `"hello"`.
- **Nil / empty** — nil and empty `[]byte` yield `""`.
- **PrintS path** — `PrintS` on `VarPrinter` with flag applies conversion (not via raw `PrintVarS(TheVar)`).
- **Flag ignored** — `BytesAsString: true` with non-`[]byte` `TheVar` uses normal dispatch.
- **Regression** — raw `[]byte` without flag still produces litter `[]uint8{...}` dump.

## Usage (target call site)

```go
// Before (eager conversion — avoid):
LOGGER.Debug("payload: %s", kt_utils.VarPrinter{TheVar: string(bytes)})

// After (lazy — v1.3):
LOGGER.Debug("payload: %s", kt_utils.VarPrinter{TheVar: bytes, BytesAsString: true})
```

For binary payloads where litter's byte dump or a future hex helper is preferred, keep raw `[]byte` in `VarPrinter{TheVar: b}` without the flag, or use `PrintVarS` directly in non-log contexts.
