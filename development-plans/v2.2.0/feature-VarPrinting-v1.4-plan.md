## Why are we doing this?

`VarPrinter` defers expensive string construction until the logger actually formats the `%s` argument. That benefit is lost when the call site prepares a value *before* wrapping it:

```go
// Eager — masking/copy runs even if DEBUG is off
LOGGER.Debug("cfg: %s", kt_utils.VarPrinter{TheVar: MaskSecrets(cfg)})
```

Typical case: a struct holds secrets a level or two deep. The service already knows how to mask (copy + redact). Masking itself is not this library’s job — but packaging the masked copy into `VarPrinter` still pays for masking when the line is later dropped.

Separately, some types need a **log-oriented** string form that is not the same as `fmt.Stringer.String()`. A dedicated hook lets types own a safe/log-specific representation without overloading `String()`. That hook must stay on the logging-oriented path (`VarPrinter`); otherwise `LogString()` and `String()` collapse into the same behavior everywhere.

**Goal:** backward-compatible, opt-in ways to (1) run an optional transform lazily at print time, and (2) let types implement a log-specific stringer used only via `VarPrinter`, while keeping existing `PrintVar` / `PrintVarS` signatures and their Stringer/error/litter semantics.

## What will be changed?

- Add `LogStringer` interface (`LogString() string`) in `pkg/kt_utils/var_printing.go`.
- Add `PrintVarWithTransform` / `PrintVarSWithTransform` that accept optional `transform func(any) any`.
- Keep `PrintVar` / `PrintVarS` as thin wrappers (`transform == nil`) for backward compatibility.
- Shared `PrintVar*` dispatch: transform → `fmt.Stringer` → `error` → litter (**no** `LogStringer`).
- Add `Transform func(any) any` on `VarPrinter`; invoke only from `Print` / `PrintS` / `String`.
- Honor `LogStringer` **only** on the `VarPrinter` path (after `Transform`, before falling through to `PrintVar*` / Stringer).
- Keep `BytesAsString` on `VarPrinter` only; apply **after** `Transform`, then existing `[]byte` handling.
- Unit tests for transform laziness, VarPrinter-only LogStringer, PrintVarS ignoring LogStringer, BytesAsString + Transform, Stringer-before-error regression.
- Create companion feature doc `docs/VarPrinting-v1.4.md`.
- Note under `CHANGELOG.md` release **2.2.0**.

**Not changed:**

- Masking / redaction logic (stays in the service).
- Litter options / meaning of `prettyPrint` (still only applies on the litter fallback).
- `PrintVar` / `PrintVarS` short-circuit order for Stringer / error / litter (aside from optional transform wrapper).

## Decisions we made

### Transform signature: `func(any) any`

- Stored and passed as `func(any) any` — no generic `AdaptTransform`, no enforced `func(T) T`.
- Same-type or different-type results are both allowed; result is fed into the normal dispatch chain.
- Call sites write a closure when they need a typed assert, e.g. `func(v any) any { return MaskSecrets(v.(MyCfg)) }`.

### `LogStringer` — VarPrinter only

```go
type LogStringer interface {
	LogString() string
}
```

- Naming follows `fmt.Stringer` / `String()`.
- **Honored only by `VarPrinter`** (`Print` / `PrintS` / `String`). That is the logging-oriented entry point.
- **`PrintVar` / `PrintVarS` / `*WithTransform` do not call `LogString()`.** They keep today’s meaning: Stringer → error → litter (after optional transform). Otherwise there would be no practical difference between `String()` and `LogString()`.
- Does not replace `Transform`: use `Transform` when the call site / service owns the prepare step; use `LogStringer` when the type owns its log representation.

### New functions; keep old signatures

```go
func PrintVar(theVar any, prettyPrint bool)
func PrintVarS(theVar any, prettyPrint bool) string

func PrintVarWithTransform(theVar any, prettyPrint bool, transform func(any) any)
func PrintVarSWithTransform(theVar any, prettyPrint bool, transform func(any) any) string
```

- `nil` transform = no-op.
- Old functions delegate to the `WithTransform` variants with `nil`.

### Dispatch precedence (locked)

**`PrintVar` / `PrintVarS` / `*WithTransform`:**

1. Apply `transform` if non-nil → `theVar = transform(theVar)`
2. `fmt.Stringer` → `String()`
3. `error` → `Error()`
4. litter dump (only step that uses `prettyPrint`)

**`VarPrinter` (`Print` / `PrintS` / `String`):**

1. Apply `Transform` if non-nil
2. If `BytesAsString` and value is `[]byte` → `string(b)` (done)
3. `LogStringer` → `LogString()` (done)
4. Else → `PrintVar` / `PrintVarS` on the (already transformed) value — **do not** pass `Transform` again

**Why keep `error` after `Stringer` in `PrintVar*`:** unchanged from today. Types like Fault implement both; preferring `String()` over `Error()` must remain.

**Note:** for `LogStringer` / `Stringer` / `error` / `BytesAsString`, `prettyPrint` is ignored (same as today’s Stringer short-circuit).

### `VarPrinter.Transform`

```go
type VarPrinter struct {
	TheVar        any
	PrettyPrint   bool
	BytesAsString bool
	Transform     func(any) any
}
```

- Transform runs only when formatting is invoked.
- `BytesAsString` after `Transform`; if result is `[]byte`, format as string; otherwise continue (flag ignored). Do not apply `Transform` twice for one format call.

### Options considered and rejected / deferred

- **Generic `VarPrinter[T]`** — fights `any` + `%s` / `fmt.Stringer` usage; rejected.
- **`AdaptTransform[T]` / enforce `func(T) T`** — extra API for little safety at the `TheVar` boundary; rejected for v1.4.
- **`func(T) E` helper** — collapses to untyped output at print time; not worth a separate helper.
- **Transform-only without `LogStringer`** — insufficient for type-owned log forms.
- **`LogStringer` on shared `PrintVar` / `PrintVarS` path** — rejected. Would erase the distinction between normal `String()` and log-specific `LogString()`; logging context is (imperfectly but usefully) signaled by `VarPrinter`.

### Explicitly out of scope (v1.4)

- Implementing `LogStringer` on types outside this repository.
- Changing litter configuration.
- Hex / base64 helpers for `[]byte`.

## Design details (locked)

```go
type LogStringer interface {
	LogString() string
}

func PrintVar(theVar any, prettyPrint bool) {
	PrintVarWithTransform(theVar, prettyPrint, nil)
}

func PrintVarS(theVar any, prettyPrint bool) string {
	return PrintVarSWithTransform(theVar, prettyPrint, nil)
}

func PrintVarSWithTransform(theVar any, prettyPrint bool, transform func(any) any) string {
	if transform != nil {
		theVar = transform(theVar)
	}
	switch v := theVar.(type) {
	case fmt.Stringer:
		return v.String()
	case error:
		return v.Error()
	}
	return litter.Options{
		Compact:           !prettyPrint,
		StripPackageNames: false,
	}.Sdump(theVar)
}

func (vp *VarPrinter) PrintS(prettyPrint bool) string {
	if vp == nil {
		return NIL_VALUE
	}
	theVar := vp.TheVar
	if vp.Transform != nil {
		theVar = vp.Transform(theVar)
	}
	if vp.BytesAsString {
		if b, ok := theVar.([]byte); ok {
			return string(b)
		}
	}
	if ls, ok := theVar.(LogStringer); ok {
		return ls.LogString()
	}
	return PrintVarS(theVar, prettyPrint) // already transformed; no second Transform
}
```

**Lazy evaluation flow (`VarPrinter` + `Transform`):**

1. Call site: `VarPrinter{TheVar: cfg, Transform: maskFn}` stores value + func; maskFn is **not** run.
2. Logger receives `VarPrinter` as `%s`.
3. If log level drops the line → `String()` never called → no transform cost.
4. If emitted → `String()` → `PrintS` → Transform → (BytesAsString | LogStringer | PrintVarS).

**Contrast — same type, two paths:**

- `PrintVarS(cfg, false)` → `String()` / error / litter (ignores `LogStringer`)
- `VarPrinter{TheVar: cfg}.String()` → `LogString()` if implemented, else same as above

## Testing

Follow existing GIVEN / WHEN / THEN style (with `t.Run` scenarios where useful):

- **Transform laziness** — side-effect/counter in `Transform` increments only when `String()` / `PrintS` runs, not when the struct literal is built.
- **Transform then dump** — transform return value is what litter / Stringer sees.
- **VarPrinter prefers LogStringer** — type with both `LogStringer` and `Stringer` → `VarPrinter` uses `LogString()`.
- **PrintVarS ignores LogStringer** — same type via `PrintVarS` uses `String()` (or litter), not `LogString()`.
- **`BytesAsString` + `Transform`** — transform runs first; `[]byte` result formatted as string when flag set.
- **Regression** — value that is both `fmt.Stringer` and `error` still uses `String()` (Fault-style).

Run: `go test ./tests/ -run 'TestVarPrinter_|TestPrintVar'`

## Usage (target call sites)

```go
// Before (eager mask — avoid when log may be dropped):
LOGGER.Debug("cfg: %s", kt_utils.VarPrinter{TheVar: MaskSecrets(cfg)})

// After — lazy transform (v1.4):
LOGGER.Debug("cfg: %s", kt_utils.VarPrinter{
	TheVar: cfg,
	Transform: func(v any) any { return MaskSecrets(v) },
})

// Type-owned log form — only via VarPrinter (v1.4):
LOGGER.Debug("cfg: %s", kt_utils.VarPrinter{TheVar: cfg}) // cfg implements LogStringer

// Ad-hoc / non-log dump — LogStringer is NOT used:
_ = kt_utils.PrintVarS(cfg, false) // Stringer / error / litter

// Direct print with transform (non-log / always-emit contexts):
_ = kt_utils.PrintVarSWithTransform(cfg, false, func(v any) any { return MaskSecrets(v) })
```
